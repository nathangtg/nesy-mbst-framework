Four Structural Bottlenecks of Pure-Neural Approaches

B1 — Hallucination

LLMs omit edges, create impossible transitions, violate system invariants — silently.

B2 — Calibration Failure

Cannot guarantee row-stochastic \(\mathbf{P}\):  \(\sum_j p_{ij}=1\), \(p_{ij}\geq 0\) — violated without warning.

B3 — State-Space Explosion

Finite context window → context fragmentation on large concurrent models.

B4 — Structural Incompleteness

Recall-limited generation misses guard–action semantics of inter-state edges.

⚠ None of these failure modes can be fixed by prompting alone

NeSy-MBST Architecture

Key principle: Neural for language-laden tasks; symbolic for formal precision.

  1. Dual-memory architecture — neural + symbolic
  2. \(L^*\) active automata learning with LLM oracles
  3. Path-dependent hierarchical modeling
  4. Symbolic constraint optimization (convex solver)
  5. Closed-loop telemetry feedback
7 / 21

Component 1 — Dual Memory Architecture

⚙ Neural Progress Memory

Fine-tuned LLM parses NL requirements and drafts a semantic flow graph.

Captures what: candidate states, events, and transitions.

✓ Symbolic Feasibility Memory

Rule-based engine enforces invariants, preconditions, and transition guards.

Ensures how: every transition is reachable, deterministic, contradiction-free.

Result: topology is both semantically plausible and mathematically sound
Avoids the end-to-end neural failure: syntactically valid yet logically inconsistent models

Component 2 — \(L^*\) Active Automata Learning

Membership Queries

"Does SUT accept sequence \(\sigma \in \Sigma^*\)?"

Oracle vocabulary: Yes / No / Unsure
Eliminates hallucinated responses entirely.

Equivalence Queries

"Is hypothesis \(\mathcal{H}\) equivalent to the target?"

Resolved by SUT execution. Counterexamples refine \(\mathcal{H}\) iteratively until convergence.

Components 3 & 4 — Hierarchical Modeling + Convex Optimization

Hierarchical Model

Upper — Higher-order Markov

\[P(s_{t+1} \mid s_t, s_{t-1}, \ldots, s_{t-k+1})\]

Frequent, path-dependent sequences

Lower — First-order Markov

\[P(s_{t+1} \mid s_t)\]

Rare / exception paths — prevents explosion

Convex Optimization

LLM extracts constraints, e.g.
\(P(\texttt{checkout}\mid\texttt{cart}) > P(\texttt{browse}\mid\texttt{cart})\)

Solver minimizes

\[\mathbf{P}^* = \arg\min_{\mathbf{P}\in\mathcal{C}}\;\mathcal{L}(\mathbf{P})\]

Max-entropy regularization  ·  \(\sum_j p_{ij}=1,\; p_{ij}\geq 0\)

Ablation Insight — Two Orthogonal Failure Modes

🔍

Symbolic Loop

Corrects structural errors

Unreachable states, missing transitions, dangling edges

MEASURED BY: F1 · COVERAGE

⚖️

Convex Optimizer

Corrects calibration errors

Miscalibrated row-stochastic probability matrix

MEASURED BY: JSD · FROBENIUS

The two components address orthogonal failure modes — both are necessary
High F1 ≠ low JSD  ·  Low JSD ≠ high coverage  ·  Three axes are independent

Adoption Guidelines

  1. Grammar-constrained oracles — restrict LLM output to Yes/No/Unsure; prevents hallucinated artefacts
  2. Symbolic verification loop before probability assignment — +35.7 pp transition coverage, 93% JSD reduction
  3. Convex optimization, not direct LLM output — JSD 0.157→0.012 via entropy-maximizing SLSQP
  4. Hierarchical multi-tier models — controls state-space explosion; preserves path-dependent fidelity
  5. Closed-loop telemetry recalibration — prevents model drift as usage patterns evolve
LLM augmentation of formal test-model generation should be standard engineering practice,
provided: (1) grammar-constrained output + symbolic loop  ·  (2) solver-assigned probabilities
